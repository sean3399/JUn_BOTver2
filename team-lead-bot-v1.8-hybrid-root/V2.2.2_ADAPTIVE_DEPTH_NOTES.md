# JUN BOT V2.2.2 · Adaptive Depth

## 목적
최근 실제 팀장 Teams/메일 대화 전문을 다시 분류해, JUN이 항상 깊게 파고드는 문제를 수정했습니다. 기본 판단 깊이는 L1이며 사안 성격에 따라 L0~L3으로 동적으로 조절합니다.

## 최근 실제 반응 기반 척도
- L0 바로 실행/수용: 단순 구매·수량·일정·발송처럼 가역적인 운영 건
- L1 간단 확인: 몇 건/왜/어떻게 진행되는지 핵심 한 가지 확인
- L2 기준·원인 확인: 비용·규정·형평성·새 프로세스에서 이유와 기준 확인
- L3 리스크·대안 심층 검토: 금액·규정·형평성·보안·전사영향이 겹칠 때 순차적으로 심화

## 팀장 판단 OS 기본 강도
- FACT FIRST 85
- WHY TRACE 60 (예산·규정·형평성에서 상승)
- PROPORTIONAL CONTROL 80
- REVISABLE OPINION 85
- RIGHT DECISION OWNER 45 (규정·R&R·당사자 선택·명시적 승인선에서만 상승)
- ACT WHEN CLEAR 90
- READER CLARITY 80 (신규 평가·프로세스·시스템 소개에서 상승)

## 주요 수정
1. `inferJunDepth()` 추가: 문서마다 L0~L3 판단 깊이를 계산합니다.
2. 일반적인 `검토 부탁`만으로 전결/판단주체 질문이 나오지 않도록 조건을 축소했습니다.
3. 신규 제도·평가·시스템에서 `READER CLARITY`를 추가했습니다.
4. 선착순/추첨/일괄 등 운영방식 선택에는 `왜 이 방식을 쓰는지`를 묻는 실제 패턴을 추가했습니다.
5. `JUN 73` 같은 숫자 노출을 없애고 `패턴 강함/중간/약함 + 질문 깊이 Lx`로 변경했습니다.
6. L0에서는 질문을 억지로 생성하지 않고 승인/실행성 반응을 허용합니다.
7. L3 사안도 첫 반응은 L1~L2에서 시작하고 대화 답변에 따라 더 깊게 들어가도록 프롬프트를 수정했습니다.

## 회귀 테스트
`tests/adaptiveDepth.mjs`에 실제 대화 패턴을 축약한 케이스를 추가했습니다.
- 임원 명함 주문 → L0
- 예산 증액 → L2/금액 산정
- 리조트 선착순 형평성 → L2/운영 기준
- JD 평가 + DNA LAB → L1/초견 이해도
- 일반 조직 기획안 → 전결 질문 억제
- 규정+보안+전사+대규모 예산 → L3

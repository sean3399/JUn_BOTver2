# JUN BOT V2.2.0 · Role Split

## 핵심 변경

### 1) JUN — 실제 팀장 반응 전용
- 문서 분석 엔진이 잡은 모든 이슈를 말하지 않습니다.
- `JUN-ness Gate`를 거쳐 실제 팀장 패턴 유사도가 높은 질문만 최대 1~2개 출력합니다.
- 문서 단계를 `기획·방향성 / 방향성 승인 / 실행계획 / 예산·투자 승인 / 최종 상신 / 일반 검토`로 감지합니다.
- 기획단계에서는 ROI, 정교한 손익표, 수요예측, 상세 통제체계 등 다음 단계 자료를 JUN이 선제 요구하지 못하게 제한합니다.

### 2) JUN Rewrite — 팀장 스타일 수정
- 이슈별로 `문장만 / 팀장식 구조화 / 상신용` 3단계 수정이 가능합니다.
- 원문에 없는 숫자·규정·담당자·일정·근거는 생성하지 않습니다.
- 사실 확인이 필요하면 `[확인 필요: ...]`를 남깁니다.
- 수정안 채택만으로 이슈를 해결 처리하지 않고, 수정본 재업로드 후 실제 이슈 소멸로 해결 판정합니다.

### 3) ADVISOR — 전문 컨설턴트 역할 분리
- 기존 6축, 근거 추적, Visual Review, 전문 개선 포인트는 ADVISOR 영역으로 분리했습니다.
- 전문 검토는 `현재 단계에서 필요한 보완`과 `다음 단계에서 준비할 사항`을 나눠 출력합니다.
- JUN 말풍선과 ADVISOR 전문 분석이 서로 섞이지 않습니다.

## Blob 파이프라인
V2.1.6의 Exact Blob URL 구조는 그대로 유지합니다.
- 모든 파일 Private Blob 업로드
- PUT 실제 URL 보존
- SDK `get(blobUrl)`로 읽기
- 파싱/OCR 후 삭제

# V2.1.5 Fix Notes

## Problem
V2.1.4 unified every attachment onto Private Blob, but added a signed `HEAD` check before `GET`. In the deployed Private Blob/OIDC setup, the `HEAD` presigned URL generation failed before the document could be read.

## Fix
- Removed signed `HEAD` entirely.
- Every attachment still uses the same Private Blob pipeline regardless of size.
- The server now creates a signed `GET` URL and retries transient `404`, `409`, `429`, and `5xx` responses.
- A successful GET is validated against the original browser file byte size.
- Presigned URL handling accepts both string and object SDK return shapes.
- Signed DELETE cleanup remains in place.

## Health check
`/api/health` should show:

{
  "version": "2.1.5-beta",
  "unifiedBlobUploadPipeline": true,
  "blobUploadMode": "all-files-oidc-signed-put",
  "blobReadMode": "oidc-signed-get-retry"
}

# V2.1.6 Exact Blob URL fix

Root cause in V2.1.5:

1. Client uploaded with a presigned PUT.
2. The PUT response contains the actual `url` and `pathname`.
3. The client discarded `url` and silently fell back to the pre-sign pathname when response metadata was unavailable.
4. The review server reconstructed a new private GET URL from `pathname` instead of reading the object identified by the successful PUT response.

Fix:
- `addRandomSuffix: false` is explicit on PUT.
- PUT response `url` + `pathname` are mandatory and carried to `/api/review`.
- Server reads the exact returned `blobUrl` with `@vercel/blob get()` + OIDC/storeId.
- Server validates `blobUrl` pathname equals the returned pathname.
- Delete uses `@vercel/blob del()` rather than another reconstructed signed URL.
- No silent fallback to a guessed object path.
